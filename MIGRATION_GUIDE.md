# Руководство по применению миграции

## Проблема
В production БД отсутствует колонка `type` в таблице `VerificationToken`, что вызывает ошибку HTTP 500 при регистрации.

## Решение

### 1. Применение миграции к production БД

Миграция `20260909_add_verification_token_type` безопасно добавляет недостающую колонку без потери данных.

#### Способ 1: Через Vercel CLI (рекомендуется)

```bash
# В корне проекта выполните:
npx prisma migrate deploy
```

Vercel автоматически использует production DATABASE_URL из environment variables.

#### Способ 2: Через Supabase Dashboard (альтернатива)

1. Откройте Supabase Dashboard → SQL Editor
2. Скопируйте содержимое файла `prisma/migrations/20260909_add_verification_token_type/migration.sql`
3. Вставьте в SQL Editor и выполните запрос
4. Проверьте, что колонка `type` добавлена:
   ```sql
   SELECT column_name, data_type 
   FROM information_schema.columns 
   WHERE table_name = 'VerificationToken';
   ```

### 2. Проверка SMTP настроек в Vercel

Убедитесь, что в Vercel настроены все необходимые переменные окружения:

- `SMTP_HOST` - хост SMTP сервера (например: smtp.mail.ru)
- `SMTP_PORT` - порт (обычно 587 для TLS)
- `SMTP_USER` - логин для SMTP
- `SMTP_PASSWORD` - пароль (должен быть секретным)
- `EMAIL_FROM` - адрес отправителя (например: "Project Tracker <your@email.ru>")
- `APP_URL` - URL вашего приложения на Vercel (например: https://your-app.vercel.app)
- `NEXTAUTH_URL` - тот же URL, что и APP_URL

### 3. Деплой обновлений

После применения миграции задеплойте обновленный код:

```bash
git add .
git commit -m "Fix: email verification with transaction and proper error handling"
git push
```

Vercel автоматически задеплоит изменения.

### 4. Тестирование

1. **Новая регистрация**: зарегистрируйте нового пользователя
2. **Получение письма**: проверьте, что письмо приходит (проверьте папку "Спам")
3. **Подтверждение email**: перейдите по ссылке из письма
4. **Вход**: войдите с подтверждённым email
5. **Повторная отправка**: попробуйте войти до подтверждения и используйте кнопку "Отправить письмо повторно"

### 5. Восстановление незавершённых регистраций

Для пользователей, созданных во время сбоя (с неподтверждённым email):

1. Они увидят ошибку при попытке входа
2. На странице входа появится кнопка "Отправить письмо повторно"
3. После повторной отправки они смогут подтвердить email и войти

## Что исправлено

✅ Создание пользователя и токена в одной транзакции
✅ Отправка email после успешной транзакции  
✅ Повторная отправка подтверждения для неподтверждённых аккаунтов
✅ Исправлена обработка SMTP-ошибок
✅ `verifyUrl` убран из production-ответа (только в development)
✅ Включена проверка `emailVerified` при входе
✅ Технические ошибки не возвращаются клиенту
✅ Rate limiting для повторной отправки (1 запрос в минуту)
✅ Безопасные ответы без раскрытия существования email

## Мониторинг

После деплоя проверьте логи Vercel на наличие ошибок:
- Ошибки создания токена
- Ошибки отправки email
- SMTP connection errors

## Откат (если понадобится)

Миграция безопасна и не требует отката. Колонка `type` имеет значение по умолчанию `'EMAIL_VERIFY'`, поэтому существующие записи останутся валидными.
