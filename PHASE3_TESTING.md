# Phase 3 Integration: Testing Guide

## Что нужно протестировать

### 1. Система прав доступа

#### Проверка ролей в проекте
1. Зарегистрируйте первого пользователя (станет admin)
2. Создайте проект - вы станете владельцем (owner)
3. Проверьте, что видите бейдж "Владелец" на странице проекта
4. Зарегистрируйте второго пользователя
5. Пригласите его в проект с ролью "Редактор"
6. Войдите под вторым пользователем
7. Проверьте, что видите бейдж "Редактор"

### 2. API с контролем доступа

#### Проверка /api/projects
- Возвращает только проекты, где пользователь владелец или участник
- Каждый проект содержит поля: `userRole`, `canEdit`, `canDelete`, `canInvite`

#### Проверка /api/projects/list
- Аналогично /api/projects, но с дополнительной информацией о владельце
- Используется на главной странице

#### Проверка /api/projects/[id]
- Проверяет права доступа перед возвратом проекта
- Возвращает 403 если нет доступа
- Возвращает информацию о роли пользователя

### 3. Страницы проекта

#### /projects/[id] - детали проекта
- Показывает основную информацию
- Отображает бейдж роли пользователя
- Показывает владельца проекта
- Навигация по вкладкам (Детали, Команда, История, Файлы)

#### /projects/[id]/team - команда
- Список участников с ролями
- Форма приглашения (только для владельца)
- Управление ролями (только для владельца)
- Удаление участников (только для владельца)

### 4. Приглашения

#### Приглашение зарегистрированного пользователя
1. Владелец приглашает по email
2. Если пользователь существует - добавляется сразу
3. Перенаправление на страницу команды

#### Приглашение нового пользователя
1. Владелец приглашает по email
2. Создается токен приглашения
3. Пользователь регистрируется
4. Переходит по ссылке /accept-invite?token=xxx
5. Автоматически добавляется в проект

### 5. Ограничения по ролям

#### Владелец (Owner)
- ✅ Просмотр проекта
- ✅ Редактирование проекта
- ✅ Удаление проекта
- ✅ Управление командой
- ✅ Приглашение участников

#### Редактор (Editor)
- ✅ Просмотр проекта
- ✅ Редактирование проекта
- ❌ Удаление проекта
- ❌ Управление командой
- ❌ Приглашение участников

#### Наблюдатель (Viewer)
- ✅ Просмотр проекта
- ❌ Редактирование проекта
- ❌ Удаление проекта
- ❌ Управление командой
- ❌ Приглашение участников

## Тестовый сценарий

### Сценарий 1: Создание и совместная работа
```
1. Пользователь A регистрируется (становится admin)
2. Пользователь A создает проект "Тестовый проект"
3. Пользователь A видит свой проект в списке
4. Пользователь B регистрируется
5. Пользователь B НЕ видит проект пользователя A
6. Пользователь A приглашает B с ролью "Редактор"
7. Пользователь B теперь видит проект в своем списке
8. Пользователь B может редактировать проект
9. Пользователь B НЕ может удалить проект
10. Пользователь A видит B в списке команды
```

### Сценарий 2: Изменение ролей
```
1. Владелец меняет роль участника с "Редактор" на "Наблюдатель"
2. Участник теперь не может редактировать проект
3. Участник видит бейдж "Наблюдатель" вместо "Редактор"
```

### Сценарий 3: Удаление участника
```
1. Владелец удаляет участника из проекта
2. Участник больше не видит проект в своем списке
3. Участник получает 403 при попытке открыть проект напрямую
```

## Миграция существующих данных

Если у вас уже есть проекты без владельцев:

```bash
npx ts-node scripts/assign-project-owners.ts
```

Скрипт назначит первого пользователя владельцем всех существующих проектов.

## Известные проблемы

1. **Старые проекты без ownerId**: Используйте скрипт миграции
2. **Prisma Client не обновился**: Остановите dev server, запустите `npx prisma generate`
3. **404 на /api/projects/list**: Убедитесь что файл создан и сервер перезапущен
